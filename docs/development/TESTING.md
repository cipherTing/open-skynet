# 开发验证结果

本文件定义 Skynet 开发任务的验证结果表达方式。它只说明如何报告已选择的验证，不替代各模块决定需要运行哪些检查。

## 三个维度

每项已选择的验证必须同时报告结果、要求级别、验证方法和可复查证据。

| 维度     | 取值            | 含义                                                                                 |
| -------- | --------------- | ------------------------------------------------------------------------------------ |
| 结果     | `passed`        | 已实际执行，命令以零状态退出，或人工审查没有发现阻断问题。                           |
| 结果     | `failed`        | 已实际执行但失败，或人工审查发现需要修复的问题。                                     |
| 结果     | `skipped`       | 已启动的测试或检查由运行器按明确条件跳过；必须写出条件。                             |
| 结果     | `not run`       | 没有启动该验证；必须写出原因。                                                       |
| 要求级别 | `required`      | 当前变更的必要证据。出现 `failed`、`skipped` 或 `not run` 时，不得宣称该变更已验证。 |
| 要求级别 | `optional`      | 有价值但不属于当前变更的必要证据，或依赖本地未提供的可选服务。它不是通过结果。       |
| 验证方法 | `automated`     | 由命令、测试或脚本得出结果。                                                         |
| 验证方法 | `manual review` | 需要人工观察或判断。未做人工审查时，结果必须写为 `not run`，不得只写“人工审查”。     |

`optional` 只能与结果一起使用，例如 `skipped / optional` 或 `not run / optional`。可选检查一旦实际执行失败，结果仍然是 `failed`，不能改写成 `optional`。

## `skipped` 与 `not run`

- `skipped` 表示命令或测试已经运行，测试框架根据可复查的前置条件跳过了检查。例如 MCP Redis 集成套件在未设置 `RUN_MCP_REDIS_INTEGRATION=1` 时由 Jest 标记为跳过。
- `not run` 表示本次根本没有启动该检查。例如页面交互审查尚未获得用户授权，或本地没有启动完整开发环境。
- 两者都不是 `passed`，也不能用于宣称“全部验证通过”。

## 报告格式

使用一项一行的表格，保留命令、前置条件和实际结果，避免用“绿了”“基本没问题”替代证据。

| 验证               | 结果      | 要求级别   | 方法            | 证据或原因                                                                                            |
| ------------------ | --------- | ---------- | --------------- | ----------------------------------------------------------------------------------------------------- |
| API 定向 Jest      | `passed`  | `required` | `automated`     | `pnpm --filter @skynet/api exec jest --config jest.config.cjs --runInBand --watchman=false <pattern>` |
| MCP Redis 集成套件 | `skipped` | `optional` | `automated`     | 未设置 `RUN_MCP_REDIS_INTEGRATION=1`，Jest 已报告跳过。                                               |
| 页面交互审查       | `not run` | `required` | `manual review` | 尚未获得浏览器审查授权。                                                                              |

只列出与当前变更有关的验证。每条 `failed`、`skipped`、`not run` 或未完成的 `manual review` 都必须在交付说明中保留，不得被汇总成通过。
