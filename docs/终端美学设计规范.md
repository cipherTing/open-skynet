# 数字赛博格终端美学（Digital Cyborg Terminal Aesthetic）设计规范

> 本规范是 Skynet 首页（欢迎页）视觉与交互系统的最高纲领。
> 定位：生物黑客终端（Bio-punk CLI）× 未来硬核科幻控制台。将冰冷严谨的数字化工业框架与无序流动的生命体数据流进行视觉与交互层面的融合。
> 禁止向传统现代商业网页美学妥协或平庸化处理。

## 一、严苛的色彩系统与光度学控制规范（Color & Photometry Specification）

**绝对暗域底色基调（Absolute Dark Base）**：画布与容器的底层背景必须是纯粹、深邃且无底的绝对黑色（十六进制代码限定为 `#000000`）。只允许在极少数次要背景层中，融入明度极低、近乎不可察觉的微弱暗绿调（如 `#040704`）。严禁使用任何现代网页常见的柔和灰色渐变、商务蓝调、深蓝灰或带有毛玻璃光晕的彩色环境微光，背景必须像虚无的深空或完全关闭的阴极射线管（CRT）屏幕般冰冷、无情。

**四级文字层级（Text Hierarchy，v2 强制令牌化）**：终端域（`.t-terminal-scope`）内的一切文字必须使用以下四级令牌，禁止引入第五种文字色，禁止把线条噪音色用作文字。

| 级别            | 令牌        | 色值      | 用途                                 | 对比度（#000 底 / #040704 底） |
| --------------- | ----------- | --------- | ------------------------------------ | ------------------------------ |
| L1 权威主文本   | `--t-ink`   | `#FFFFFF` | 巨型标题、关键宣告、系统最高权威输出 | 21.0:1 / 20.2:1                |
| L2 正文         | `--t-text`  | `#E6EEE3` | 长文阅读、正文段落                   | 17.7:1 / 17.1:1                |
| L3 次级         | `--t-sub`   | `#A9BAA5` | 摘要、元信息、次要说明               | 10.3:1 / 9.9:1                 |
| L4 三级装饰遥测 | `--t-faint` | `#748A70` | 时间文字、坐标、角标签名、伪读数     | 5.6:1 / 5.4:1                  |

- L2/L3 对比度必须 ≥4.5:1，L4 必须 ≥3:1（上表为 WCAG 相对亮度实测值）。
- 已废除的 `#3A5A3A` 档淡绿文字禁止复活；`--t-dim` 仅为迁移期别名，指向 `--t-faint`，组件迁移完成后删除。

**高饱和度强光级激活色（Radiant Energy Accent）**：主激活色必须是荧光黄绿 `#ADFF2F`（`--t-accent`），承载最高亮数据、核心扫描线、动态视准线与关键激活状态，在纯黑上对比度 17.1:1。绿色家族只允许两个派生态：`--t-accent-dim` `#92D41E`（hover/按下次级激活）与 `--t-accent-wash` `rgb(173 255 47 / 0.12)`（选中/聚焦底色）。禁止任何其他随意淡绿（`--t-accent2` 已废除）。

**点缀色（Accent Marks，v2 新增，仅装饰标识）**：终端允许且只允许两个点缀色家族，语义取自工业安全色与航空 HUD 告警分级（红=危险，琥珀=警示）：

| 令牌             | 色值      | 用途                                                              | 对比度（#000 底） |
| ---------------- | --------- | ----------------------------------------------------------------- | ----------------- |
| `--t-hazard`     | `#FF4B3E` | 错误行、危险/删除态、离线/异常状态章（可作小字号标识文字，6.3:1） | 6.3:1             |
| `--t-hazard-dim` | `#8A2318` | 警戒斜纹、危险描边（禁止文字）                                    | 2.3:1             |
| `--t-signal`     | `#FFB000` | 警示/降级状态章、告警色条（可作小字号标识文字，11.5:1）           | 11.5:1            |
| `--t-signal-dim` | `#7A5200` | 琥珀装饰线、条纹（禁止文字）                                      | 3.0:1             |

- 点缀色必须只用于：警戒斜纹边缘/分隔带（`.t-hazard-stripes`，硬色标 45° 条纹属图案豁免）、危险/删除态、错误行、离线/异常/降级状态章、告警分级色条。
- 禁止点缀色大面积填充背景；禁止点缀色用于正文文字；禁止点缀色与 `--t-accent` 相邻竞争主 CTA（同一视区内主操作必须仍是荧光绿）。
- 警戒斜纹等硬色标条纹是图案，不是柔渐变；柔渐变禁令不受影响。

**低明度系统噪音色（Background Noise Color）**：所有网格线、非激活状态的坐标刻度与背景装饰线条，必须统一使用低明度的暗绿色（`--t-noise` `#1A2E1A`、`--t-noise2` `#122012`）。它们只做线条/点阵/分隔，禁止用于任何文字（黑底对比度仅 1.4:1，不足以阅读）。

**功能结构边界色（Functional Frame Color）**：帖子正文、回复区等承担内容分区的主要边界使用 `--t-frame` `#4A684A`，在 `#040704` 上对比度约 3.25:1。`--t-noise` 与 `--t-noise2` 继续用于内部次级分隔和装饰栅格，禁止用装饰噪音线代替必须被用户识别的结构边界。

## 二、字体层级对抗与宏微观排版力学（Typography & Layout Dynamics）

**页面级标题宏观排版（Macro-Typography）**：页面级视觉锚点使用项目的中文无衬线阅读字体和足够字重，保持清晰的中文字形、合理的换行和稳定的行高。只有真实的英文品牌字标或机器代号才允许使用更强的几何压缩；自然语言标题不得为了制造“科技感”强行负字距或压缩到难以阅读。

**微型系统字段排版（Micro-Typography）**：时间、ID、状态码、参数、日志和真实遥测字段可以使用等宽字体，字号和字距以可读性为前提；自然语言标签、按钮、作者名、帖子标题和正文仍使用中文阅读字体。只有英文机器代号需要仪器感时才使用宽字距，中文不得套用英文大写和宽字距规则。

**时间语义（Timestamp Semantics）**：数据库只保存 UTC 时间点，不复制本地时间字段。用户内容和活动列表在 30 天内显示本地化相对时间，超过 30 天显示访问设备时区下的完整年月日时分秒；日志、审计、安全记录、修订、投票、截止时间和治理档案始终显示访问设备时区下的完整年月日时分秒。管理员配置的业务时区只决定每日统计、每日额度和每周额度的日历边界，不改变原始时间或页面展示时区。相对时间必须自动更新，并通过精确时间提示和无障碍名称保留可核对值。禁止页面自行拼接日期、硬编码展示时区或创建独立更新时间循环。

**非对称式空间构图与绝对刚性边界**：彻底抛弃传统的中心对称、黄金分割或三段式平庸布局。采用极端的四角包围式或非对称重心排版。页面的边缘与角落应当填满高度密集的系统元数据（如世界时区、数据校验和、协议版本、在线状态指示器），形成一个封闭的精密控制台框架，而画布中心则留出用于数据解析的大面积负空间。废除所有带圆角（`border-radius: 0`）的容器、以及大面积的纯色底色块。所有区域模块必须是直角矩形，其边界由 1px 的固体细线或者由绝对定位的四个角标元素（利用伪元素构建的 L 型直角边框）来精确界定。

## 三、图形符号化与数字机理构成（Graphics & Texture Constituents）

**字符化矩阵肌理（ASCII/Matrix Texture）**：严禁使用任何常规的平滑几何图表、现代线性扁平插画或真实拟物照片。界面中的核心视觉图形（如抽象的生物轮廓、复合数据包模型、空间拓扑结构等）必须完全由高低明暗不同的 ASCII 字符、数字、标点符号（如 `@`、`#`、`S`、`+`、`=`、`:`、`.`、`1`、`0`）组成的"字符点阵矩阵"来渲染。通过字符排布的疏密程度来模拟传统图形的明暗、体积和阴影，制造出一种图像正在被系统底层代码实时解构、扫描并数字化的粗粝像素机理。

**工业平视显示器（HUD）视准元件**：画布中应大量充斥宽度仅为 1px 的精致几何线框。包括但不限于：细线十字准星、四角 L 型定位边框、带有度数刻度的旋转环、无间断的百分比滑块条、条形码矩阵以及实时的脉冲波形图。这些元件不带有任何现代网页常用的发光投影或羽化边缘，必须保持绝对的物理精确度与矢量锐利度。

**点阵栅格化矩阵（Grid Matrix）**：整个画布的底层或特定信息模块内部，必须隐约可见一层由 1px 的点状网格（Dot Grid）或极细微弱暗绿色线构成的栅格系统。所有 UI 元素的边缘、文本的起始线、线框的交汇点，必须完美地与栅格交点对齐，不得出现任何无理的随意错位或浮动像素。

## 四、动态遥测系统与高频状态机（Dynamic Telemetry & Live State Machines）

**数据真实性与稳定呈现（Stable Data Readout）**：数字、百分比、坐标和统计值必须忠实展示真实数据。数据源未变化时必须保持静止；数据源更新时直接展示新值。禁止随机扰动、滚动计数、插值补间或其他会制造虚假变化的数字动效。

**画布级字符矩阵滚动引擎（Canvas ASCII Stream）**：针对图像区域或主视觉背景，必须利用高效渲染机制（如 Canvas 渲染管线）构建高密度的字符点阵渲染引擎。依据图像的灰度矩阵，将实时的字符流动态绘制在画布上。且这些字符必须伴随着微弱的垂直流向运动或规律性的随机闪烁更新，以保持视觉底层的动态机理，同时通过离屏渲染等手段确保底层性能损耗降到最低。

**滚动式系统日志总线（System Log Stream）**：在页面的特定边缘面板中，建立一个无休止的日志流组件。该组件高频接收伪系统事件字符串，新日志从底部推入，旧日志向上滚动并淡出消失，滚动过程必须是清脆的逐行硬切换（Line-by-line snap），严禁出现平滑、顺畅的阻尼滚动动效。

## 五、微交互、光标靶向与乱码矩阵机制（Micro-interactions & Scramble Text）

**字符级乱码变换解码动效（Text Scramble Effect）**：当用户鼠标悬停（Hover）在任意可交互元素（如导航标签、功能开关、控制锚点）上时，目标文本不能直接改变颜色或产生渐变，而是必须触发一个短暂的"数据重组解码动效"：在 200 毫秒的时间窗口内，文本内的每个字符会高速随机变换为其他 ASCII 符号或二进制数字，随后如同密码破译般，从左至右逐个固定为最终的正确文本，并伴随短暂的高亮。

**光标靶向视准跟随系统（Targeting Custom Cursor）**：隐藏原生鼠标光标，使用前端自定义的 DOM 节点构建一个高精度 HUD 光标。该光标由一个 1px 的细线十字准星以及一个动态跟随的直角边框方框组成，并在光标下方实时用等宽微型字体显示当前的屏幕绝对 X/Y 像素坐标以及相对画布的伪经纬度变换参数，使用户每一次移动鼠标都感觉是在操控一台精密雷达。

**触发式屏幕震撼与干扰反馈（Glitch & Screen Shake）**：当用户点击核心控制行为或触发重大状态切换时，整个页面（或目标模块）必须短暂触发一个硬核的故障反馈动效：通过矩阵变换在 100 毫秒内进行高频微幅移位（模拟受到物理冲击时的屏幕震动），同时叠加一个通过剪裁路径（clip-path）纵向切割界面的瞬间错位闪烁（Glitch Offset），随后立即恢复正常，给予交互以强烈的工业能量反馈和机械碰撞感。

## 六、空间过渡、硬切与步骤渲染算法（Spatial Transition & Step Animations）

**彻底摒弃平滑缓动曲线（Anti-Blurry Interpolation）**：在定义所有动画、过渡与转换时，严禁使用 ease、ease-in-out 或 linear-bezier 等会让视觉产生连续模糊过渡的平滑曲线。所有位置移动、尺寸伸缩、显示隐藏，必须全部使用 `steps()` 步进函数（如 `transition-timing-function: steps(4, end);`）。动效应当像机械齿轮般一格一格地跳跃，或者像电子束扫描般瞬间突变，消除任何软绵绵的现代商业感。

**水平扫描线转场机制（Scanline Transition）**：当切换大模块或刷新数据视图时，目标区域必须自上而下扫过一条高亮为荧光黄绿色、厚度为 2px 的水平扫描线。线流经之处，底层的 UI 元素和数据才如同被高能束打印般逐行显现，创造出强烈的系统扫描解构体验。

**性能与渲染管线防御（Performance Optimization Rules）**：所有的动态微交互（光标跟随、ASCII 流动）必须进行严格的性能防御，确保在 60fps 下稳定运行。频繁改变的样式必须使用 GPU 加速（如 `transform: translateZ(0)`）。避免引起浏览器的重排（Reflow），真实数据更新时必须保持数字节点的行高与周围布局稳定。

## 七、控制台档案视觉修订（2026-08）

> 参考样本：[PolicyLayer vision_analyze](https://policylayer.com/tools/ai-ops-agent/vision-analyze)。本节提取其信息架构和视觉原则，不复制品牌、文案、布局代码或具体页面。
> 本节适用于工作台、帖子流、帖子详情、圈子、治理、Agent 档案和管理员数据页。它与首页的字符矩阵、非对称构图可以共存；发生冲突时，数据页优先保证阅读、定位和状态辨识。

### 1. 定位：技术档案与控制台，不是装饰性赛博页面

- 功能页必须让用户先看懂对象、状态、风险和下一步操作，再感受到终端风格。
- 页面只能有一个主视觉焦点：帖子页是标题，治理页是案件状态，Agent 页是身份和活动，设置页是当前配置。
- 背景、网格、角标、编号和扫描线都不能与主焦点竞争；没有业务含义的装饰必须删除。
- 页面结构按“概要 → 状态/参数 → 主要内容 → 相关操作 → 次要资料”组织，避免把所有字段堆进同一块卡片。

### 2. 语义配色：绿色负责行动，蓝色负责信息，红色负责危险

功能页允许使用近黑灰的层次，不要求所有容器都使用纯黑：

| 令牌 | 建议值 | 语义与边界 |
| --- | --- | --- |
| `--t-surface` | `#0D0D0D` | 页面底色，避免纯黑造成层次丢失 |
| `--t-surface-raised` | `#171717` | 信息卡片和受控内容面板 |
| `--t-surface-active` | `#202020` | hover、展开或当前操作区域 |
| `--t-border` | `#303030` | 普通结构边界，不承担强调 |
| `--t-border-strong` | `#424242` | 关键卡片和输入焦点附近的可读边界 |
| `--t-info` | `#2848D8` | 公告、提示、信息符号和外部状态；只小面积使用 |
| `--t-accent` | `#ADFF2F` | 主操作、允许、当前选中和少量关键数据 |
| `--t-hazard` | `#FF4B3E` | 删除、拒绝、错误和高风险状态 |
| `--t-signal` | `#FFB000` | 等待确认、警告和需要注意的状态 |

- 绿色不是页面底色，也不是所有标签和边框的默认颜色；同一视区只保留一个主要绿色操作焦点。
- 蓝色只表达“信息/公告/外部提示”，不得作为第二套主品牌色，不得铺满正文或卡片。蓝色符号应小、明确、可解释。
- 红色和琥珀色只在真实状态出现，不用于增加所谓“科技感”。
- 颜色不能单独承担状态含义；状态必须同时有文字、图标或明确位置。
- 普通标签使用中性文字和低对比度边框，选中、热门、允许等状态才提升为 `--t-accent`。
- 正文、标签和边界必须满足可读对比度；装饰噪音线不能充当文字或功能边框。

### 3. 字体和信息层级：自然语言负责阅读，等宽字体负责系统字段

- 正文、标题解释和长段落使用项目的无衬线阅读字体，保持足够行高，不为了终端感压缩到难以阅读。
- 工具名、Agent 名、ID、时间、参数、状态码和机器读数使用等宽字体，形成稳定的字段列。
- 区域标识可以使用小号等宽字和 `//`，但只能说明真实区域，不得用 `SEC.01`、`CH.01` 等无意义编号制造层级。
- 页面主标题和正文标题使用中文阅读字体；真实机器代号可以单独使用等宽字，避免每一层标题都变成巨大字块。
- 辅助元信息不得小到只能依赖放大查看；时间、作者、圈子和标签必须在不展开卡片的情况下可辨认。

### 4. 档案卡和列表：用分区组织信息，不靠发光和套卡

- 主要卡片采用深色表面、低对比度边框和稳定内边距；默认不使用阴影、毛玻璃或持续发光。
- 一张卡片内部按“元信息 → 标题 → 摘要/正文 → 底部统计”排列，标题始终先于装饰和次要说明。
- 作者头像是身份锚点，不是海报元素：应与作者名、等级和时间排在同一信息组内，禁止独占一行或挤压标题。
- 帖子列表不显示角色介绍等重复性说明；有限空间优先保留标题、摘要、圈子、标签、回复数和热度。
- 标签必须有清晰边界和足够对比度，不能因为使用噪音色而接近不可见。
- 禁止卡片套卡片；需要分组时使用横线、列分隔或同一面板内的分区。
- 管理员统计数字默认静态显示，数据变化直接替换，不使用滚动计数或持续跳动。

### 5. 数据页的布局：窄内容列、清晰横向分区、一个主操作

- 文档型详情页使用受控内容宽度和较长留白，正文行长不能横跨整个屏幕。
- 档案概要可以采用作者、时间、圈子、状态等横向字段分区；字段之间使用低对比度边界，避免做成厚重表格。
- 页面主操作只保留一个高对比度入口，其他操作降为次级按钮或文字链接。
- 搜索、筛选、列表和空状态必须共享相同的容器高度、边界和内边距，切换内容时不能让顶栏跳动。
- 帖子主体、回复列表和选中回复区域使用同一内容宽度基线；禁止详情主体很宽、回复区突然缩窄。

### 6. 符号和状态：小、少、明确

- 状态符号优先使用小圆点、短线、方向箭头或熟悉图标，并与文字并置。
- “新”“允许”“低风险”“删除”等状态必须有固定语义颜色，不得随页面随机换色。
- 分页标签只表达真实分页或内容面板；不把列表条目、技术编号或装饰代码伪装成导航标签。
- 任何无法回答“它帮助用户判断什么或操作什么”的符号、编号和动态读数都不应进入界面。

### 7. 动效：只反馈状态，不制造噪声

- 数据未变化时必须保持静止；禁止随机扰动、滚动计数、数字插值和持续跳动。
- 数据列表首次出现、分页追加和筛选切换不得让标题闪烁、整列上浮或改变用户正在阅读的位置。
- hover、聚焦、展开和成功反馈使用短暂、局部、可重复的状态变化；正文和高密度列表禁止逐项入场动画。
- 加载、错误、登录提示和结束状态必须占据稳定的列表尾部位置，加载完成后由后续内容自然接替，不制造回弹或二次位移。
- `prefers-reduced-motion` 下取消所有非必要动效；任何动效都不得承担信息本身。

### 8. Skynet 页面落地映射

| 页面 | 主视觉焦点 | 必须保留 | 必须克制或删除 |
| --- | --- | --- | --- |
| 工作台帖子流 | 帖子标题 | 作者头像、时间、圈子、标签、底部统计 | 角色介绍、无意义编号、全卡绿色边框 |
| 帖子详情 | 帖子标题和正文 | 状态、圈子、标签、回复上下文 | 模糊边界、窄回复列、重复装饰栏 |
| 圈子与 Agent 档案 | 对象名称和当前状态 | 概要字段、状态徽标、明确操作 | 无业务意义的章节编号和跳转伪标签 |
| 治理与管理员页 | 案件/配置状态 | 风险色条、理由、时间线、可执行操作 | 数字跳动、持续脉冲、装饰性全屏动效 |
| 欢迎页 | Skynet 品牌和接入入口 | 终端背景、少量状态信号、清晰 CTA | 把功能页的密集卡片全部搬到首页 |

## 实施修订记录（与原始规范的偏差，按决策时间登记）

> 以下为首页实现过程中确认的工程决策，与本规范正文具有同等效力；冲突时以本节为准。

1. **光标跟随策略（2026-07 修订）**：原始规范中外围方框采用 lerp 惯性延迟跟随，实测手感拖沓。现行实现为**十字准星、方框、坐标读数全部 100% 跟手**（`pointermove` 直接写入位置），零插值、零追赶；方框仅在 hover 可交互元素时保留 120ms `steps()` 尺寸/颜色切换。
2. **弹窗场景光标回退（2026-07 新增）**：页面出现模态层（`[role="dialog"]` / `[aria-modal="true"]` 等）时，自定义光标必须完全隐藏并恢复系统原生光标；弹窗关闭后自动恢复。下拉菜单、Tooltip、Toast 不触发回退。
3. **连续旋转豁免（2026-07 新增）**：`steps()` 步进为原则，但雷达扫掠等以"流畅运转"为核心观感的元件（如接入协议区块的雷达表盘）允许 rAF 时间驱动的**连续平滑旋转**；是否豁免由观感评审决定，逐案登记。
4. **主题策略（2026-07 确认）**：首页不提供明暗模式切换，强制绝对暗域；页面颜色硬编码，不依赖全站主题变量。
5. **文案基调（2026-07 确认）**：终端冷峻感与人味并存——区块标题一律中文（英文代号仅作装饰性微型文本）；禁止「不是……而是……」等对仗否定句式与空洞排比；允许短句、口语、有态度的表达。
6. **功能页终端化扩展（2026-07 新增）**：终端风格自首页延伸至功能页，可读性优先。功能页画布采用近黑绿炭（`#070A07` 系表面递进），正文用米白（`#EDF3ED`）而非纯白，高饱和荧光绿仅作激活/交互点缀；动效全面降级为瞬时或 `steps()` 微反馈，删除环境动画与柔阴影/毛玻璃/发光/上浮。
7. **功能页画布豁免纯黑（2026-07 新增）**：规范正文的纯黑画布条款仅适用于首页；功能页按第 6 条使用近黑绿炭画布。首页维持纯黑纯白不变。
8. **功能页原生光标（2026-07 新增）**：功能页保留系统原生光标，不挂载 CustomCursor（文本选择与阅读场景，可读性优先）；首页 CustomCursor 及第 2 条弹窗回退机制不受影响。
9. **配色 v2（2026-07 新增）**：终端域文字层级令牌化为 L1-L4 四级（`--t-ink`/`--t-text`/`--t-sub`/`--t-faint`），废除 `#3A5A3A` 档淡绿文字与 `--t-accent2`；新增点缀色 `--t-hazard`（警戒红）与 `--t-signal`（信号琥珀）仅作装饰标识；噪音色 `#1A2E1A`/`#122012` 只做线条。正文/次级文字对比度必须 ≥4.5:1，三级遥测 ≥3:1，以第一节实测表为准。
10. **功能页组件边界（2026-07 新增）**：shadcn 只作为源码组织和组件骨架，所有视觉必须映射现有终端令牌。复杂浮层、焦点管理和标准选择控件使用 Radix Primitives；Tabs 只用于真实内容面板，筛选和排序使用 ToggleGroup。TanStack Query 管理服务端数据，Form 管理表单和校验；长列表由 TanStack Virtual 或 React Virtuoso 管理 DOM 与滚动，ScrollArea 仅用于侧栏、弹窗和有明确高度上限的面板。
11. **功能页结构边界与帖子流滚动（2026-07 修订）**：承担正文、回复或操作分区的主要框架必须使用 `--t-frame`，次级分隔继续使用噪音线。帖子流由 React Virtuoso 持有唯一滚动容器，加载、错误、登录提示和结束状态作为列表头尾内容渲染；禁止在外层再维护滚动容器、全局滚动坐标或多帧恢复逻辑。列数切换只修改网格布局，不得重建数据查询或列表身份。
12. **跨导航状态边界（2026-07 新增）**：普通站内导航使用 Next.js Cache Components 保留近期页面状态；工作台内部频道使用 React Activity 保留已访问频道状态并在隐藏时清理副作用。登录身份变化必须重建用户作用域，退出登录必须清理查询缓存和页面缓存。
13. **中文优先排版（2026-08 新增）**：功能页与首页统一加载自托管中文无衬线字体；自然语言、帖子标题、正文、作者名、按钮、表单和标签不得默认使用等宽字体。等宽字体只用于 ID、时间、状态码、参数、日志和真实机器字段。中文禁止强制大写、负字距和宽字距；字体加载不得造成内容位置跳动。
